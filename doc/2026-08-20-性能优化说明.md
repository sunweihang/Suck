# 2026-08-20 性能优化说明

本文整理 8 月 20 日当天对战斗帧、启动首屏、关卡资源、GPU 合批所做的全部优化。目标读者是后续改玩法或改渲染的人：先讲**为什么慢**，再讲**原理**，最后落到**代码怎么写、写在哪**。

当天仓库在 `master` 上，相关提交从早上的 `68a9876`（单 Pass 实例光照）一直到晚上的 `56a1be8`（两 draw 画完全墙）。中间有一次「同色砖合并成大 Mesh」的尝试（`60052e7`），当天中午已经回退（`8397218`），原因写在第 7 节。

---

## 0. 问题从哪来

这是一款体素墙射击关卡。官方图有 **430 关**，全部展开大约 **95 万颗体素**。典型关卡是一座实心雕塑：玩家看到的只是外壳，内部大半颗砖永远看不见。

优化前的代价大致是：

| 阶段 | 旧做法 | 代价 |
| --- | --- | --- |
| 启动 | 拉一份约 10MB 的 `catalog.json`，立刻把 430 关解码成对象 | 首屏卡死、微信包体积大 |
| 建世界 | 每颗砖 `instantiate` 一份颜色预制体，再靠换 Layer 藏起来 | 节点、MeshRenderer、材质、GPU 描述符全量创建；每帧还要被相机剔除扫一遍 |
| 旋转墙 | 每帧改 2000+ 个节点的 `worldMatrix` | CPU 脏标记爆炸，合批被拆碎 |
| 战斗帧 | 每帧全量扫墙、哈希占位、木筏逐砖写坐标 | 拖转/射击时掉帧 |
| 破碎 | 每击打一组独立碎片 + 独立材质 | draw call 和分配一起涨 |

当天的工作可以分成四条线，后面按这条顺序写：

1. **启动与资源**：先画出首页，关卡和 3D 世界后置、分片、并行。
2. **建世界**：盒内砖不建渲染器；共享立方体网格后挂。
3. **GPU**：一张自定义 effect，实例颜色进顶点流，墙的旋转进 shader uniform。
4. **战斗帧**：外壳扫描、稠密网格、增量可见性、木筏父节点、组件休眠、特效预算。

## 1. 启动与资源管线

### 1.1 原理：首屏只需要 UI，不需要墙

旧启动是一条长 `await` 链：开 bundle → 解全部关卡 → 建当前关世界 → 拉 UI 图 → 拉音频 → 拉背景。任何一步的网络等待都是死时间，而且首页还没画出来就已经在实例化几千颗砖。

拆开之后，启动变成两段：

```
Splash（宿主首屏像素）
  → 只开 UI bundle + 画 BootLoad
  → 首页可点
  → 后台预取 play bundle + 当前关世界
Play
  → 世界已在则直接进
  → 否则再走关卡加载条
```

### 1.2 分包：`loadHomeBundles` 与 `loadGameBundles`

`assets/scripts/boot/LoadBundles.ts` 把资源分成两包：

- **Home**：`resources` + `prefabs`，只 `loadDir(resources, 'ui')`。首页图、按钮、BootLoad 够用。
- **Play**：在 Home 之上再拉 `prefabs` 的 `models / materials / blocks / units / board / fx / ui`，以及 `resources` 的 `audio / toys / meshes / fx`。

两段都做成单例 Promise（`_homeJob` / `_playJob`），重复调用会复用，失败才清空以便重试。`GameBootstrap._bootUi()` 在首页画出来之后立刻 `void loadGameBundles()`，不阻塞 `_showHome()`。

### 1.3 并行启动：`bootStep` 吞掉单步失败

`GameBootstrap` 里每个可并行任务包一层 `bootStep(tag, job)`：失败只 `console.error`，不把整个 boot 打进 fallback。首页先 `await preloadHomeArt()`，UI 全套、胜利音效、3D 背景在 `_warmAfterHome` 里后台跑。

Splash 还用 `afterDraws(n)` 等引擎真正画完再通知宿主藏首屏，避免「逻辑 ready、画面还是黑的」。主相机在 BootLoad 画出来之前保持 `DEPTH_ONLY` 且 `enabled = false`，避免 `SOLID_COLOR` 把公司首屏像素清掉。

### 1.4 延迟建世界 + 首页预取

`_bootWorld()` 不再出现在 splash 路径。`_showHome()` 末尾调用 `_prefetchPlayWorld()`，在玩家看首页的时间里把当前关 `buildPlayWorld` 跑完。进 Play 时：

- `_playWorldReady()` 为真 → `_revealPlay()`，不再弹 BootLoad。
- 从首页点「开始」但预取未完 → `_ensureWorld()` 等同一个 `_bootJob`，不重复建。
- 过关进下一关 / GM 跳关 → `_runLevelLoad` 显示加载条。

世界用 `_bootEpoch` 作世代号。玩家中途回首页或进 UGC，旧的异步建造结果会被丢掉（`PlayWorld_abandoned`），避免把过期关卡挂上场景。

回首页时如果打过这一关（`_worldTouched`），会拆掉 `PlayWorld` 再预取，避免带着战斗中间态的墙回去。

### 1.5 胜利彩带预热不再打一整轮粒子

`WinConfetti.warmupWinConfetti` 只造一个隐藏发射器，打 4 颗、等 2 帧、销毁。目的是让粒子 shader / 贴图上传发生在 splash 期间，而不是第一次弹出胜利面板时卡一帧。真正的 `playWinConfetti` 才组完整 volley，并且把发射器数量收过一轮（5 组碎片 + streak/star/rain，不再是每张碎片图各开一路）。

引导小手 `HintHand` 在没有路径之前保持 `active = false`，避免空转 `update`。

## 2. 关卡数据：分片、按需解码、LRU

### 2.1 原理：10MB 目录不该进首包热路径

旧 `assets/resources/levels/catalog.json` 大约 9.86MB，启动时整份 fetch + `JSON.parse`，再把 430 关、约 95 万体素展开成 JS 对象。玩家这一次只打一关。

现在拆成：

| 文件 | 角色 | 体积量级 |
| --- | --- | --- |
| `levels/catalog.json`（仓库根，**不进 assets**） | 策划/工具的权威源 | ~10MB |
| `assets/resources/levels/index.json` | 运行时只读 `{ count, size, shards }` | 36 字节量级 |
| `assets/resources/levels/p000.json` … `p042.json` | 每片 10 关 | 按关加载 |

`tools/level-io.js` 的 `writeShipShards()` 在每次写目录时重切分片，避免源和包漂移。当前 index：

```json
{"count":430,"size":10,"shards":43}
```

### 2.2 运行时：`ensureLevels` / `ensureLevel` / `getLevel`

`assets/scripts/game/LevelCatalog.ts`：

1. `ensureLevels()` 只拉 index，设 `LEVEL_COUNT` 和 `SHARD_SIZE`。**不解析任何关卡。**
2. `ensureLevel(id)` 按 `(id - 1) / SHARD_SIZE` 算片号，拉 `levels/p00N`。同片并发共用一个 `SHARD_JOBS` Promise。
3. `getLevel(id)` 必须在 `ensureLevel` 之后调用，保持同步。它只 `decodeLevel` 当前这一关。
4. 原始分片缓存在 `SHARDS`，最多留 **6** 片，超出按插入顺序淘汰并 `resources.release`。
5. 解码后的 `LevelDef` 缓存在 `DECODED`，最多留 **4** 关（当前关附近保持热）。`Map` 的插入顺序当 LRU：命中时 delete + 再 set。

`decodeLevel` 才做体素展开、色板对齐、炮台 token remap。启动路径里的 `await ensureLevels()` 不再触发这份工作。

调用约定：

```ts
await ensureLevel(this._level);
const level = getLevel(this._level);
```

`GameBootstrap._bootWorldInner` 和 `buildPlayWorld` 都遵守这条。GM 跳关、过关进下一关同样先 `ensureLevel`。

### 2.3 UGC 存储只 parse 一次

`UgcStore.loadAll()` 用模块级 `_cache`。这个模块是 `SAVE_KEY` 的唯一写者，写回时同步更新 cache，读路径不再每次 `JSON.parse` localStorage。

## 3. 世界构建：盒内砖不建渲染器

### 3.1 原理：实心雕塑里 58% 的砖永远看不见

统计过 430 关：954,827 颗体素里，关卡开始时只有 394,942 颗能被相机看到（约 41.4%）。旧流程对每一颗都 instantiate 预制体，再换 Layer 藏起来。MeshRenderer 仍然挂在渲染场景里，每帧走裁剪。

新规则：

- **六面都被邻居堵住**的体素：只建空 Node + `BlockCell`，`meshless = true`。
- **外壳**：挂共享立方体 + 共享材质（或进入实例批次，见第 4 节）。
- 挖开之后，`setBrickDrawn` 第一次给它 mesh；`BattleDirector` 建完索引后会用 `_isBuried` 再验一遍，建图时猜错最多浪费一个 renderer，不会漏画。

### 3.2 建图时的盒内判定

`BuildPlayWorld.boxedInVoxels` 用整数键 `(x+1)*128+(y+1))*128+(z+1)` 做六邻域：

```ts
solid.has(x±1) && solid.has(y±1) && solid.has(z±1)
```

六个方向都有实体才算 boxed-in。锁砖、木筏砖在运行时 `_isBuried` 里被排除（它们必须能被点到）。

`placeBrick` 在已经拿到共享 cube mesh（`readyMesh`）时不再 instantiate 颜色预制体，只 `new Node` + `BlockCell`。所有颜色预制体指向同一份立方体，所以任意一份加载成功就能 `rememberBrickMesh`。

### 3.3 共享立方体后挂：`hang` 与 `attach`

`BrickSpecials.ts`：

- `rememberBrickMesh(mesh)`：建图时记下那份共享 cube。
- `hangBrickRenderer(node)`：先加空 `MeshRenderer`（关阴影），**不赋 mesh**。`addComponent` 的代价发生在建图，而不是挖开那一帧。
- `attachBrickRenderer(node, colorId)`：赋共享 mesh + `brickMat(rgb)`。注释写明：赋 mesh 会重建 model，所以组件要提前挂好，揭示帧只付一次赋值。

`brickMat` 按 RGB 缓存 `makeFieldUnlit`，同色砖共用一份材质。这是「停止给每颗砖 mint 一份 field material」的核心：每多一份 field 材质，shader 旋转每帧就要多 set 两次 uniform，并多拆一个 draw batch。

### 3.4 后台预热：挖开一层时不要一次建几十个 model

把 renderer 推迟之后，代价会堆到「挖开 / 炸弹」那一帧。`BattleDirector._warmBuriedMeshes` 每帧最多：

- 扫描 96 个 `meshless` 槽（`MESH_WARM_SCAN`）
- 真正 `attachBrickRenderer` 8 个（`MESH_WARM_PER_FRAME`）

`_hideBuried` 会把 `_meshless` 排个序：先暖紧贴外壳的，再暖更里面的。玩家剥到它们之前，mesh 多半已经挂好。`setBrickDrawn` 仍保留按需路径，预热没赶上的那一颗当场补。

GPU 实例合批开启后（第 4 节），内部砖不再需要私有 MeshRenderer，`_warmBuriedMeshes` 直接 return。

### 3.5 揭示只重建一次

`51075fe` 修的是：一颗刚露出来的砖会被三条路径各建一次 model（layer 切换、paint、skin）。现在统一走 `setBrickDrawn` → `attachBrickRenderer`（或进 batch），`forgetBrickParts` 清掉部件缓存，避免脏列表。

## 4. GPU：单 Pass 光照、Shader 旋转、两 Draw 画墙

这是当天收益最大的一块，也是后来「合 Mesh」失败后真正站住的方案。

### 4.1 单 Pass 实例光照：`brick-lit.effect`

Cocos 默认 `builtin-standard` 是多 Pass（base / forward-add / shadow）。几千颗塑料方块不需要那套。`assets/resources/fx/brick-lit.effect` 做成 **一个 opaque pass**：

- 主光 Lambert + 移动端 GGX（`GGXMobile`）+ `BRDFApprox`
- 天光 / 地光按法线 Y 混合
- 环境反射用视线反射向量再混一次天空色
- `roughness / metallic / emit` 打进 `pbrParams`

`ToyBlockMesh.makeInstancedLit` 优先用这份 effect，失败才回退 `builtin-standard`。炮台、砖、道具、碎片都走它。`USE_INSTANCING` 打开时，同材质实例可以被引擎合批。

阴影整关关掉（`GameBootstrap._tuneLighting`：`shadows.enabled = false`，方向光 `shadowEnabled = false`）。方块不投影，省掉 shadow pass。

### 4.2 Shader 旋转墙：不要每帧脏 2000 个矩阵

墙在休息时会慢转，拖动时会快转。旧做法改每个砖节点的世界矩阵 → 2000+ 次 dirty + 合批失败。

新做法：砖的节点停在 **rest 空间**（未旋转的局部坐标）。GPU 在 vertex shader 里绕 `spinPivot` 用 `spinQuat` 转一次：

```glsl
vec3 p = wp.xyz - spinPivot.xyz;
p = quatRotate(spinQuat, p);
wp.xyz = p + spinPivot.xyz;
v_worldN = quatRotate(spinQuat, v_worldN);
```

`FieldSpin.ts` 维护：

- 当前 `_q` / `_p`（四元数 + 轴心）
- 所有 field 材质的集合 `_fieldMats`
- 每份材质的 pass handle（`spinQuat` / `spinPivot`），用 `pass.setUniform` 直写，避免 `mat.setProperty` 的属性查找

`BattleDirector._poseFieldSpin` 只在 `_spinRot` 相对上次 `_posedRot` 变了才上传。`FieldActors`（挡板、木筏板、飞出后的辅助物）仍然吃节点旋转；墙体砖吃 shader 旋转。

砖飞出墙时必须「烤」进世界空间，否则会带着 shader 旋转继续飞：

```ts
releaseFieldNode(node, swapMats)
  → bakeOffField：rest 坐标 × spinQuat 写成 world
  → swapMats：换掉带 spin 的 field 材质，换成 freeTwin（同色但不注册 field）
```

`BlockCell._leaveField` 在吸走 / 炸飞时走这条。之后改走飞行实例批次（见 4.4）。

射线检测、瞄准、提示手的世界坐标用 `restToWorld` / `worldToRest` / `fieldWorldOf`，和 GPU 看到的位置一致。

### 4.3 材质缓存：同色必须是同一份 Material

`cachedFieldLit` / `BrickSpecials._mats` / `DebrisBit._chipMats` 都按「颜色 + 粗糙度 + 金属度 + 自发光」做 key。原则写在 `ToyBlockMesh`：

> 每一份不同的 field 材质，墙转的时候每帧会被重新 set 两次 uniform，并且自己占一个 draw batch。道具绝不能按实例 mint。

油漆罐、炸弹等特殊砖也改成复用，不再每颗一份。幽灵炮台共用 ghost 材质。

碎片拖尾、玩具描边打开 `USE_INSTANCING`，同材质才能合进引擎实例缓冲。

### 4.4 两 Draw 画全墙：自定义实例流

「按颜色各开一个 batch」（`5029bac`）还是会按调色板拆出十几次 draw。晚上改成（`56a1be8`）：

- **Rest 批次**：墙上静止的可见砖，**1 次 draw**
- **Fly 批次**：吸走 / 炸飞中的砖，**1 次 draw**

颜色不再靠材质分批，而是打进实例顶点：

| 属性 | 格式 | 内容 |
| --- | --- | --- |
| `a_matWorld0/1/2` | RGBA32F | 世界矩阵的三行（含平移） |
| `a_instColor` | RGBA32F | 线性空间前的 0–1 RGB |

`BrickSkin.writePacked` 每个实例 16 个 float（64 字节）。`bindInstanceStream` 在共享 cube 的 vertex buffer 后面再挂一条 instance buffer，`instanceCount` 等于当前砖数。

Shader 侧用 `USE_BRICK_INSTANCING && !USE_INSTANCING`：

- **不用**引擎的 `USE_INSTANCING`。否则这个 host MeshRenderer 自己会再走一遍引擎实例缓冲，变成「1 个实例画 1 个 host」。
- `brickWorld()` 从 `a_matWorld*` 拼 `matWorld` / `matWorldIT`。
- 片元：`albedo = mainColor.rgb * (v_instColor.rgb * v_instColor.rgb)`（实例色按 sRGB 再平方进线性）。

`makeBrickBatchMat` 的 define 只有 `USE_BRICK_INSTANCING`。Rest 材质注册进 `FieldSpin`（吃墙转）；Fly 材质不注册——飞砖的旋转已经烤进 `worldMatrix`。

每帧 `tickBrickSkin`：

- Rest：只有 `dirty` 才重传 VB（挖开、上灰、位移、锁定时 `markBrickSkin`）
- Fly：有成员就每帧重传（位置每帧在变）

砖进批次时关掉自己身上的 body MeshRenderer（`hideBody`）；退出批次再 `showBody`。不支持 `INSTANCED_ARRAYS` 的设备走 `fallbackDraw`，退回每砖一个 renderer。

`inflateFieldCull` 把共享 cube 的 AABB 扩到 ±18，避免实例中心在 host 原点时被相机裁掉整墙。

### 4.5 飞行砖与道具占位

`6b5c5e0`：钩子 / 铲子的目标在道具飞行动画落地前占住座位（`_fxHoldUnit` / `_fxHoldSlot`），避免动画期间别的炮台抢座。飞砖走 `flyBrickSkin`，不回退成私有 mesh。

## 5. 战斗帧

### 5.1 外壳扫描，不再全墙 + 哈希占位

可见性只关心「没被埋住的砖」。`_hideBuried` 维护 `_shell`。`_rebuildCamVis` 只扫 `_shell`，不扫 `_blocks`。

占位从 `Map` / 字符串 key 改成稠密数组：

```
index = layer * layerStride + row * cols + col
_grid[index] = BlockCell | null
```

`_aliveAt` / `_setCell` / `_clearCell` 都是 O(1)。沙子下落、木筏换列用 `_relocate`：只改这一颗在 grid / `_byCol` / `_byRow` 里的位置，**不** `_indexBlocks` 重建整墙。

### 5.2 相机可见性：增量 + 节流

`_visibleSet` 用 `_visBucket()`（相机朝向量化）+ ghost 标志 + `_visGen` 做 key。

- 砖被挖走：邻居丢进 `_visPatch`，`_patchCamVis` 只重测种子周围，不全量重建。
- 拖转时 bucket 每帧都变：瞄准可以落后几帧。旋转中每 **10** 帧才重建（`VIS_SKIP_SPIN`），静止每 **8** 帧（`VIS_SKIP_REST`）。
- 盒内砖（`buried`）直接跳过，它们不可能通过 `_camExposed`。

命中列表按 RGB 和 colorId 各建一份（`_visByRgb` / `_visByColor`），炮台找同色外壳时不用扫全 shell。

### 5.3 Shader 旋转的 CPU 上传

`_tickField` 里四元数没变就 return。变了才 `_poseFieldSpin` → `setFieldSpin`。`setFieldSpin` 自己再做 `Quat.equals` / `Vec3.equals`，重复值不写 GPU。

有 handle 时走 `pass.setUniform`，没有才 fallback `mat.setProperty`（兼容 builtin-standard）。

### 5.4 木筏：父节点位移，不逐砖写

旧：每帧给木筏上每颗砖 `setPosition`。新：

1. `_mountRaftCarry` 把木筏砖挂到 `Wall/RaftCarry`，本地坐标写成 rest 座位。
2. `_placeRaft` 只动 `RaftCarry` 的 `(offset, bob, 0)` 和木筏板节点。
3. 列号按 `round(offset / blockStep)` 变化时才 `_relocate` + `_reindexCols`。

逻辑占位仍正确（射击按列算），渲染是一次父节点平移。

前排炮台缓存 `_frontByCol`，bench 探路不再每帧扫全部座位。

### 5.5 把 update 从引擎调度器上拿下来

Cocos 对每个 `enabled` 的 Component 调 `update`。静止的砖、排队的炮台占大头。

**砖 `BlockCell`：**

- `onLoad` / `syncFromName` 立刻 `this.enabled = false`。
- 只有位移、抖动、吸走、炸飞时 `_armMotion()`，推进模块级数组 `_motion`。
- `BattleDirector.update` 调 `BlockCell.tickMotion(dt)`。
- 动作结束 `_restMotion()`，从数组摘掉。

**炮台 `UnitActor`：**

- 排队且已摆好姿势、没有滑动 / 飞行 → `_canSleep()` → `enabled = false`。
- `UnitActor.animLive` 跟 `setPlaying` 走，结算面板期间整排停动画。

**提示手：** 无路径不激活。

### 5.6 教程探测节流

`GuideContext` 复用同一个对象，避免每帧分配。墙在转时降低 bench / wall 探测频率。道具教学：图标飞到 HUD 落地后才 `setItemsReady(true)`，避免引导点在空槽上。

## 6. 破碎与胜利特效预算

### 6.1 `DestroyBurst`：共享池 + 每帧限额

对齐原 VoxelDestroy 的预算思路（`DestroyBurst.ts` 头注释）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `MAX_BUDGETED_PER_FRAME` | 2 | 每帧最多新开 2 次击打 |
| `MAX_CONCURRENT` | 24 | 同时存活的击打事件 |
| `PARTICLES_PER_HIT` | 6 | 每次击打的碎片数 |
| `MAX_CHIPS` | 64 | 池上限；超出复用寿命最短的 |

同色碎片共用 `makeInstancedUnlit` 材质。方块本体仍 `blowOff`（自己飞出去），碎片是附加的「渣」。超预算直接不喷，战斗不卡。

`DebrisBit` 碎片拖尾同样实例材质；池子上限 22。

### 6.2 结算时关掉 3D 世界

`_sleepPlayWorld`：`PlayWorld.active = false`，主相机改 `SOLID_COLOR` 清天空色。胜利 / 失败面板和彩带不再跟几千颗砖抢 fill rate。

## 7. 当天试过又撤掉的方案

### 7.1 同色墙合并成共享 Mesh（`60052e7` → `8397218`）

想法：把同色静止砖焊成几张大皮，draw 从「每砖一次」降到「每色一次」。

失败原因：合并后的 skin **不能**再走引擎 instancing（否则整张皮变成一个实例，位置错）。关掉 instancing 才能看见，但一旦关了，draw 和 uniform 成本比「每砖一份实例」更差。飞砖还要从 batch 里挖出来，CPU 更抖。

回退后 `BrickSkin` 的对外钩子留成空操作，避免改调用方。真正的两-draw 方案是晚上重写的自定义实例流，不再依赖引擎 `USE_INSTANCING` 画墙。

### 7.2 删掉的玩法砖

`4bd35a8` 去掉磁铁、油漆罐、墙炸弹三种未使用砖。关卡解码仍会吞掉旧存档里的 `*` / `!` / `^` 标记，避免脏数据炸 decode。少几种预制体 = 少几份材质和微信包体。

## 11. 后续改时不要踩的坑

1. **不要给单颗砖 `new Material()`。** 先查 `brickMat` / `cachedFieldLit` / `makeBrickBatchMat`。新材质 = 新 draw + 每帧多两次 spin uniform。
2. **墙上的砖不要改 world 旋转来表达场旋转。** 改 `BattleDirector._spinRot`，让 `FieldSpin` 上传。飞出去必须先 `releaseFieldBrick`。
3. **不要给 rest batch 开 `USE_INSTANCING`。** host 会被引擎当成 1 个实例；墙要用 `USE_BRICK_INSTANCING` 读我们自己的 VB。
4. **`getLevel` 前必须 `await ensureLevel`。** 否则抛「shard not loaded」。
5. **盒内判定只是加速。** 真值以 `_isBuried` 为准；锁砖、木筏砖永远不算埋住。
6. **合 Mesh 这条路已经验证过更亏。** 要再降 draw，优先扩实例流（例如挡板、木筏板），不要焊大皮。
7. **预热 mesh 是为非 batch 设备留的。** `brickSkinBatched()` 为真时不要再 `attachBrickRenderer` 给内部砖，否则又把私有 mesh 加回场景。
