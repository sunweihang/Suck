# 服务器接口说明

服务端负责微信小游戏登录和玩家存档。当前存：**当前关卡、金币、道具**。客户端仍先写本地，登录成功后再和云端合并。

实现目录：`server/`。客户端入口：`assets/scripts/net/PlayerCloud.ts`。

对齐文档：

- [小程序登录](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/login.html)
- [auth.code2Session](https://developers.weixin.qq.com/minigame/dev/api-backend/open-api/login/auth.code2Session.html)

---

## 1. 登录流程

按微信规范做**自定义登录态**。`code` 只能用一次；`session_key` 只留在服务端，不下发。

```
客户端 wx.login()
        ↓ 临时 code（约 5 分钟）
POST /v1/auth/login  { code }
        ↓
服务端 GET https://api.weixin.qq.com/sns/jscode2session
      ?appid=&secret=&js_code=&grant_type=authorization_code
        ↓ 得到 openid、session_key（及 unionid，若已绑开放平台）
服务端签发 token（默认 7 天）
        ↓
后续 GET/PUT /v1/player
Header: Authorization: Bearer <token>
```

没有 `wx.login`（Creator 预览）或 `code` 换票失败时，若服务端 `ALLOW_GUEST=1`，客户端会改走游客：`{ guest: true, guestId }`。正式环境必须关掉游客。

## 2. 启动

```bash
cd server
cp .env.example .env
# 填 WX_APPID / WX_SECRET
npm i
npm run dev          # 热重载
# npm start          # 只跑一次
```

默认 `http://127.0.0.1:8787`。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `WX_APPID` | 空 | 微信公众平台 → 开发管理 → 开发设置 |
| `WX_SECRET` | 空 | 同上，只放服务端，禁止写进小游戏包 |
| `ALLOW_GUEST` | `1` | 正式环境改 `0` |
| `TOKEN_TTL_SEC` | `604800` | 登录态秒数（7 天） |
| `DATA_DIR` | `./data` | 存档 JSON 目录，不入库 |

探活：

```bash
curl -s http://127.0.0.1:8787/v1/health
```

---

## 3. 约定

所有 JSON 接口使用微信风格信封：

```json
{ "errcode": 0, "errmsg": "ok", "data": {} }
```

失败时 `errcode != 0`，`errmsg` 为人读说明。部分错误另带 HTTP 状态（未登录 `401`、冲突 `409`）。

鉴权：`Authorization: Bearer <token>`。`GET /v1/health`、`POST /v1/auth/login` 不需要。

跨域已放开（`*`），方便网页预览；微信 `wx.request` / Cocos `XMLHttpRequest` 不依赖 CORS。

## 4. 接口

### `GET /v1/health`

探活，无需登录。

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "data": { "ok": true, "wx": false, "guest": true }
}
```

`wx` 表示是否已配置 AppId + Secret。

### `POST /v1/auth/login`

用微信 `code` 或游客身份换 token，并带回当前存档。

微信登录：

```json
{ "code": "081x..." }
```

游客（仅 `ALLOW_GUEST=1`）：

```json
{ "guest": true, "guestId": "gxxxxxxxx" }
```

`guestId`：`8–64` 位字母数字、`_`、`-`。同一 id 视为同一玩家。

成功：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "data": {
    "token": "…64 位 hex…",
    "expiresIn": 604800,
    "player": {
      "level": 1,
      "coins": 200,
      "items": { "shuffle": 0, "hook": 0, "shovel": 0, "bomb": 0 },
      "rev": 0,
      "updatedAt": 1710000000000
    }
  }
}
```

新用户 `rev` 为 `0`。响应不含 `openid`、`session_key`。

### `GET /v1/player`

拉存档。需要 token。

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "data": {
    "player": {
      "level": 4,
      "coins": 350,
      "items": { "shuffle": 1, "hook": 0, "shovel": 2, "bomb": 0 },
      "rev": 1,
      "updatedAt": 1710000000000
    }
  }
}
```

### `PUT /v1/player`

推存档。需要 token。必须带上次拿到的 `rev`。

```json
{
  "level": 5,
  "coins": 400,
  "items": { "shuffle": 1, "hook": 0, "shovel": 2, "bomb": 1 },
  "rev": 1
}
```

成功则 `rev` 加一，返回最新 `player`。

`rev` 对不上（两台设备同时写）返回 HTTP `409`：

```json
{
  "errcode": 40901,
  "errmsg": "存档版本冲突",
  "data": { "player": { "level": 4, "coins": 350, "items": {}, "rev": 1, "updatedAt": 0 } }
}
```

客户端应合并后用服务端 `rev` 再推。

字段钳制：关卡 `1–200`，金币 `0–10^9`，每种道具 `0–9999`。

---

## 5. 错误码

| errcode | HTTP | 含义 |
| --- | --- | --- |
| `0` | 200 | 成功 |
| `40000` | 400 / 404 | 缺字段、JSON 无效、路径不存在 |
| `40001` | 401 | 未带 token 或已过期 |
| `40013` | 502 | 未配置 AppId / Secret，或微信报 invalid appid |
| `40029` | 400 | `code` 无效（微信同号） |
| `40301` | 403 | 未开放游客登录 |
| `40901` | 409 | 存档 `rev` 冲突 |
| `50000` | 500 | 未捕获异常 |
| `50010` | 502 | 调微信失败 |

微信 `code2Session` 的其它 `errcode`（如 `-1` 系统忙、`45011` 频控、`40226` 高风险拦截）会原样返回。

---

## 6. 存档与合并

| 字段 | 含义 |
| --- | --- |
| `level` | 当前可玩关卡（过关后 +1，与本地 `suck.level` 一致） |
| `coins` | 金币（与 `suck.wallet.v1` 一致） |
| `items` | `shuffle` / `hook` / `shovel` / `bomb` 持有数 |
| `rev` | 服务端版本，客户端不可自增 |
| `updatedAt` | 服务端写入时间（毫秒） |

登录后合并规则：

- 云端 `rev == 0`（从未成功写过）：以上传本地为准
- 否则关卡、金币、各道具分别取较大值
- 合并结果与云端不同则再 `PUT`

本地仍是兜底：网络失败不影响开玩。

教程、宝箱周期、UGC 地图仍只存在本地，本版不同步。

## 7. 客户端怎么接

| 文件 | 作用 |
| --- | --- |
| `assets/scripts/net/GameServerConfig.ts` | 服务地址。`PROD_BASE_URL` 填正式 HTTPS；空则开发版走 `http://127.0.0.1:8787`，**正式版不请求** |
| `assets/scripts/net/PlayerCloud.ts` | `wx.login`、拉存档、防抖推送、冲突重合 |
| `GameBootstrap` | 钱包加载后 `initPlayerCloud` |
| `PlayerWallet` / `LevelCatalog` | 本地保存时 `notifyPlayerDirty()` |

上线前改一处：`GameServerConfig.ts` 里的 `PROD_BASE_URL`。

## 8. 微信后台与上线

1. `server/.env` 填真实 `WX_APPID`、`WX_SECRET`，`ALLOW_GUEST=0`。
2. 服务必须 HTTPS。在公众平台 → 开发管理 → 开发设置 → **request 合法域名** 填主机名（不含路径、不要端口）。
3. 开发者工具打本地地址时勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。
4. 正式包不要把 AppSecret、`.env`、`server/data` 打进小游戏。
5. 域名需按微信要求备案。

本地联调示例（游客）：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8787/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"guest":true,"guestId":"testuser01"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["token"])')

curl -s http://127.0.0.1:8787/v1/player -H "Authorization: Bearer $TOKEN"

curl -s -X PUT http://127.0.0.1:8787/v1/player \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"level":3,"coins":250,"items":{"shuffle":0,"hook":1,"shovel":0,"bomb":0},"rev":0}'
```
